# Round 2 item 7 — low-poly crop growth-stage models behind LookDev

Date 2026-11-19. Branch `track/c-world-look`. Status `SEEN-IN-STUDIO`.

## Target

Low-poly growth-stage models (bibit / tumbuh / siap) for every crop in `Config/Crops` — all 12
crops, 36 models total — shown in an in-world showcase behind `LookDev`. Every model is a
CANDIDATE awaiting a designer yes/no: none approved, none shipped on by default. Colours come
from the `ART.md §3` palette; no asset IDs.

## Approach

The queue asked for low-poly models behind `LookDev`. As with item 6, imported meshes were not
viable (subagent transport down, place saves forbidden). The models are therefore **pure-data,
source-controlled Roblox primitive-part recipes** behind an off-by-default `crops` LookDev
candidate: durable in Rojo, reversible, no place save, no asset IDs. They do not touch the
shipping crop visuals that `FarmService` builds on real tiles.

## What was made

- `src/shared/CropModelCandidates.luau` — pure data + pure functions, no Roblox APIs at load.
  A `partsFor(cropId, stage)` function expands an archetype (stem / leaves / fruit / optional
  accent) into a flat list of part descriptors for the requested stage. bibit = two-leaf seedling
  with no fruit; tumbuh = full leaves with small fruit; siap = full mature silhouette. 12
  archetypes, one per crop in `Config/Crops.order`.
- `src/client/World/LookDevCrops.luau` — the client applier. On enable it builds a floating
  6-column grid of all 36 models near the player (each cell: a soil base, the recipe parts, and a
  BillboardGui label), and on disable destroys every created instance. Shape resolution is
  best-effort (see Studio note below).
- `LookDev.luau` gains a sixth pure-data `crops` candidate (`idsSource` pointer, no numeric IDs,
  `cropCount = 12`, `stageCount = 3`), booted behind `pcall` in `Main.client.luau`. The gallery
  render is generated from the **same** `partsFor()` via a Lune dump, so it cannot drift.

## Studio proof (Play Solo, fresh Client VM, Rojo `localhost:34872`)

- `LookDev.IDS` = `plaza_lighting,police_walkin,icons,textures,npcs,crops`;
  `hasApplier("crops")` = true.
- `enable("crops")` returned `true` with no warning; `current()` = `crops`.
- Showcase (models / BaseParts): `0/0` → `36/339` → (after `disable()`) `0/0`. **36 models built,
  all removed.** Sample names: `LookDevCrop_padi_bibit`, `LookDevCrop_padi_tumbuh`,
  `LookDevCrop_padi_siap`.
- 339 parts = 303 recipe parts returned by `partsFor()` across all 36 models + 36 Soil base parts
  (the BillboardGui labels are not BaseParts). The Lune probe computed `expectedParts = 303` from
  the same `partsFor()` the adapter uses, confirming the adapter renders exactly the shipped data.

**Restricted-VM note.** The Studio MCP `execute_luau` sandbox cannot resolve `Enum.PartType`
shape members, so `shapeOf()` resolves them under `pcall`: on failure Parts keep Roblox's default
Block shape, so all 36 models still build and the toggle is fully proven. The real LocalScript VM
resolves Cylinder/Sphere/Wedge.

## Render

`docs/v2/visual/art/crops/render/contact_sheet.png` is generated by
`docs/v2/visual/art/crops/src/generate_crop_preview.py`, which first runs
`docs/v2/visual/art/crops/src/dump_crops.luau` in Lune to dump `partsFor()` for all 12 crops x 3
stages, then draws a front-elevation schematic per cell. It is a **review aid derived from the
shipped recipe data**, not a Studio screenshot (this session cannot save `screen_capture` to disk).
The live enable/disable proof above is the evidence of record. No agent visually graded the art;
the schematic is for the designer's yes/no only.
