== Method ==
Fresh Play. pcall-required all 42 server applier modules so registration is not vacuous. Staged all
13 via enableAdditive(id, game, {studio=true}); confirmed 13 distinct `<Module>_<id>` folders.
For CROSS_OVERLAP: enumerated every BasePart in each of the 13 folders by name suffix, computed the
full 3D AABB from CFrame*Size corners, binned into 8-stud XZ spatial hashes, and compared parts from
EVERY pair of DIFFERENT candidate folders (78 folder pairs) with a 0.5-stud tolerance (touching faces
are not overlaps). COLLIDABLE parts only (the item's literal CanCollide==true filter); an all-parts
scan ran alongside as informational. Loader calls stage fresh within each run (disableAll first), so
the two runs are independent. Then disableAll and the full 79-ID LOOKDEV_LEAK sweep.

== ANTI-VACUITY (why the first naive result was rejected) ==
A first pass filtered parts by CanCollide==true and got partCount=0 — a VACUOUS pass. Investigation:
ALL round-9 lookdev dressing parts are intentionally CanCollide=false (decorative, non-blocking);
there is no collidable geometry to overlap by design. NOT a folder-match bug — correct enumeration
by folder finds 35,949 parts. Fixed by adding a guard: the check now requires stagedOk AND 13 staged
folders AND parts>0 AND unreadable==0 AND not-capped. A 0-part / missing-folder / unreadable-part
result now emits FAIL, never PASS. The literal spec check (collidable pairs) is reported together with
the all-parts informational count so the empty collidable domain is explicit, not hidden.
