== Real bug found and fixed (NOT allowlisted) ==
The pre-fix console (captured in Edit mode before this item's fresh Play) had nine
`smoke_r8: could not build ParticleEmitter <id>: Unable to assign property Lifetime. NumberRange
expected, got NumberSequence` warnings, repeated across earlier full_r9 staging plays. Root cause:
`src/client/World/LookDevSmokeR8.luau:77-78` set `ParticleEmitter.Lifetime` and `.Speed` with
`NumberSequence.new(...)`; both properties are `NumberRange` on Roblox, so `buildEmitter` pcall
failed and warned once per emitter (9 emitters). Fixed both to `NumberRange.new(...)`. This is the
other two same-symptom FarmService emitters already use NumberRange
(`src/server/Farm/FarmService.luau:248-249,265-266`). A new spec case in
`tests/specs/smoke_r8_spec.luau` locks `pe.Lifetime`/`pe.Speed` to `NumberRange` and forbids
`NumberSequence` for them, so the bug cannot regress silently. NO allowlist entry hides this line:
`smoke_play_spec.luau` asserts the allowlist contains neither `smoke_r8: could not build
ParticleEmitter` nor `NumberSequence expected`.

After the fix, two fresh-Play 60 s windows (default look and full_r9 staged) produced ZERO
smoke_r8 warnings — the fix is effective in Studio, not just in source.

- `ORDER = { "SMOKE_CLEAN" }`, `emit(name, passed, measured, target, detail)` prints
  `CHECK <name> PASS|FAIL <measured> <target>` and returns

- `ALLOWLIST`: 5 entries, each `{ text, reason }` with a one-line reason. Deliberately short:

  `ShippingLookR7: no PlotAnchor parts ... flower beds painted` shipping ground-look notice (dev
  place has no PlotAnchor parts; unrelated to lookdev staging). No game-code error is allowlisted.
- Classification: every non-empty console line is either allowlisted WITH a reason or counted as a
  violation. There is no "info ignored" bucket, so an error-level message can never pass silently.
  `SMOKE_CLEAN` passes iff `#violations == 0`; measured = violation count, target = 0.
- Console readback is main-session only: Luau cannot call the MCP `get_console_output` tool, so the
  main session snapshots `get_console_output()` after the 60 s wait and feeds the exact lines to
  the harness via `_G.SMOKE_CONSOLE_LINES`. The harness file itself is pasted whole into
  execute_luau (Server VM). Output log resets on a fresh Play in this session, so no stale-prefix
  subtraction was needed; the harness documents the multiset-delta method for sessions where the
  log accumulates.
