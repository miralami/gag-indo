== THREE REAL ERRORS FOUND AND FIXED (none allowlisted or check-weakened) ==
1. First stage attempt built only 37/50 parts: 13 parts (6 walls, 4 roof tiers, 3 window panes)
   warned `[LookDevMusalaR8] could not stage part <id> for <kind>`. Root cause: those recipes used
   material token `Painted`, which is NOT a member of Roblox's Enum.Material in this Studio, even
   though `LookDev.BUILTIN_MATERIALS` listed it. FIXED: all four musala tokens -> `Plastic` (colour
   still comes from Color3, so the green roof reads the same), the stale `Painted` allowlist entry
   was removed, and `musala_r8_spec` now forbids that token. A fresh Play then staged all 50 parts
   with ZERO musala warnings.
2. `MUSALA_DOOR_CLEAR` pose check initially FAILED: Roblox `CFrame.LookVector` is a Part's local
   -Z, but the harness compared it directly against the outward (+Z) direction. FIXED: compare
   `-LookVector` to the outward radial direction, with a comment and a spec guard, so the check
   tests the real door orientation instead of failing a correct staging.
3. `MUSALA_PATH_REACH` initially reported 17 false blockers: the kit is yaw-rotated, so world-axis
   AABBs (`bboxAABB`) are much larger than the real footprints (base platform, roof tiers, etc.).
   FIXED: transform each tagged part back into the SITE-LOCAL frame (inverse yaw, project its basis
   onto local +X/+Z) and compare its local XZ box to `Data.CORRIDOR` with `OVERLAP_TOL=0.05`. This
   keeps the check strict — it still tests every staged part and still requires zero overlaps —
   while measuring in the frame the geometry was authored in. Spec guards lock both fixes.
