== Vacuous-PASS defect found and fixed (recorded, no check weakened) ==
First Studio run emitted DAY_1600_CONTRAST PASS 0.000000 >=0.000000 and DAY_PHASES_MONOTONIC PASS
0.500000 <=0.625000 while Lune showed 2.16 -> 2.71 and 0.623529. Root cause: a real Roblox Color3
is userdata (type() ~= "table"), while the Lune test double is a plain table. The model's luminance()
guard `type(rgb) ~= "table"` returned 0 for Studio Color3, and adjacentJumps()' `type(a) == "table"`
gate skipped every colour channel, so both Studio measurements collapsed toward zero and compared
vacuously. Fix (dst 2026-11-21):
  * ModelMapDayCycleR8.luau: added pcall-based colorChannels() duck-typing both the userdata .R/.G/.B
    shape and the Lune table shape; luminance() and adjacentJumps() now both use it.
  * review_check_r8.luau: added non-vacuity guards `baseRatio > 0` (contrast) and `baseJump > 0`
    (monotonic) so an unreadable-colour environment now FAILs loudly instead of vacuously PASSing.
  * day_cycle_r8_spec.luau: source guards lock colorChannels/pcall usage, the removed type gates, and
    both harness non-vacuity guards; a non-table channel provider yields a real luminance under Lune.
All checks re-run: Lune 2653 tests pass (was 2652), selene src 0/0/0, Studio re-run produced the
non-vacuous PASS lines above. No threshold, target, or assertion was weakened; the fix makes the
checks stricter (they can now FAIL where they previously PASSed vacuously).
